# Capabilities — what this engine does, what it does not, and what holds that true

**True against engine 3.61.2**, container format 1.12, 485 test files and 4514 tests passing.

The single map. Anything else claiming to list what is missing is either older than this file or
is a plan for closing one of its rows. Established by reading the tree rather than the release
notes: every `absent` row below names a sentinel symbol, and `scripts/docs.test.mjs` asserts each
one is still missing, so the commit that builds a capability is the commit that has to correct
this document.

| Lighting        | Directional with cascaded shadows (rotated Poisson, receiver-plane compensation); ten point lights with cube shadows; ray-marched light volumes with a dust field, a sun-shadow cut, and — a medium the beam answers to: `medium` on the draw scales the volume by the haze at the _volume's own_ height against the density it was authored for, so a headlight cone fades as the air clears and is skipped entirely in clear air. The shader's own header had said since it was written that a beam is more visible in fog and nothing implemented it; the same cone was drawn in soup and on a clear night, which a consumer reported as fog filtering the frame rather than changing what could be seen through it. A multiplier on the CPU in `lightVolumeDraw.ts` rather than a uniform, because the shader clamps strength to one and the value is per draw, so both backends read the one function and no shader changed. Driven by `demo/dev/volume.html?fog=` **Environment probes stand on a grid, 3.49.0.** `ProbeGrid` places them on a lattice and `nearestProbes` returns the eight around a point with trilinear weights; a single baked probe is a grid of one, so there is one path and every scene that bakes an environment keeps the picture it had — measured against `main` on the same GPU, within about one level of 255 on every figure `ibl-check.mjs` publishes, with the no-probe control identical. **It costs no texture unit.** Fifteen of WebGL2's guaranteed sixteen are spent and one is left, so the `samplerCube` became a `TEXTURE_2D_ARRAY` of octahedral maps at the same binding: levels 0 to 4 are the GGX chain and level 5 is a cosine convolution, so one sampler carries the reflection and the diffuse ambient both and unit 15 stays free. That retired the spherical-harmonic path outright — `irradianceSh.ts`, `probeReadback.ts`, the synchronous `readPixels` in the bake, and the second gate uniform that existed because one backend's ambient landed a frame or two after its reflection. **A filtered octahedral map needs a gutter**, which the point-shadow array never did at one level and `NEAREST`: the square's border is a fold, and a texel filled by that rule matches the one it is folded against to 3.3e-16 against 4.6e-2 without it. Probes cost layers rather than units, capped at `MAX_ENV_PROBES` of 64 — 683 KB a layer, 43.7 MB for the lot, against the point-shadow array's 92.3 MB. **21,495 gzipped bytes on `core-only`, 3.33%**, of which the generated WGSL is 16,502. Checked by `scripts/probegrid-check.mjs`: fifteen assertions on both backends agreeing to 0.23 levels, with a repeat-measurement floor of 0.00, and both distinguishing claims written from mutations | Post            | Bloom, output transform, exposure, **a colour grade as a 3D lookup table**, ambient occlusion, camera motion blur, speed rush, MSAA, frame veil **Refraction ships and completes Track D**: a copy of the frame's colour, latched at the first refracting draw, sampled at an offset along the surface normal and absorbed by Beer-Lambert. **9.05 KB gzipped over core** against the 19.8 KB the census had priced it at — a uniform and a branch in `flatFrag`, not a permutation, so the fragment stage stays at sixteen. | Surfaces        | Gerstner water, caustics, planar reflection, wet film with roughness, reflection probe, procedural sky and atmosphere, fog, grain, relief. **A body of water is a rotated rectangle**: `bounds` was a centre and one half-extent, so the only shape it could take was a square, and the square that contains a 3 by 21 metre channel floods eighteen metres of ground either side. Reported from outside, where the workaround was one _unbounded_ body at the ditches' level with the world's whole ground raised above it — a technically flooded world held up by a rule nobody can see, which had already cost one bug. `halfX` and `halfZ` are the body's own axes and `forwardX`/`forwardZ` say which way they point, a direction and not an angle because a consumer bounding a ditch arrives holding the run's direction; `halfM` stays as the square shorthand. What it cannot do is bend, so a canal that turns is one body per straight run. **And a frame can draw more than one body, which on WebGPU it could not**: every body's uniforms lived in one buffer rewritten before each draw, and a queue write does not interleave with the draws it sits between, so four bodies all wore the fourth's extents, level and colours — 387,837 pixels of one frame, measured. A slot each now, from a `UniformRing`, which is the rule in `AGENTS.md` reaching the pass that was still missing it. Driven by `demo/dev/water.html`, four bodies in one frame with one of them turned, at 56 pixels between the backends **A four-lane per-vertex channel, 3.42.0**: `MeshData.channel` carries `sway` in the vertex stage, `skyDirect` for the directional term alone and `alpha` on the draw's opacity, in one `vec4` at attribute location 13 — one location because WebGL2 guarantees sixteen, eleven were spent and an instanced draw spends all of them, so `InstancedMesh` refuses a mesh carrying one rather than reading the absent constant and drawing leaves that never move. Absent is `(0, 1, 1, 0)` through the same disabled-attribute mechanism `grain` and `relief` use, so a mesh that says nothing costs no buffer and is identical to the digest — measured, `f0092361` on both backends. **`skyDirect` multiplies `sunShade` and not `direct`**, because the sun's specular lobe reads `sunShade` on its own and scaling the diffuse alone leaves an enclosed face with no sunlight and a highlight anyway; ambient is untouched, which is the defect it exists to fix — a sky factor folded into `colors` scales ambient and sun together and darkens a cave face twice. **Sway reads the wind `resolveScatterDeform` already produces**, through `setWind` once a frame and bound to the depth pass too, so a canopy and its own shadow bend together; the lane is taken as authored where `scatter.ts` squares its own, because that falloff is derived from height and this one is written by hand. **5.8 KB gzipped over core** and no new permutation on either stage — the vertex stage is 5 variants at 5.2 KB against the fragment stage's 16 at 283.4 KB, which is why a vertex channel is not priced like a fragment branch. | Draws           | Instanced scatter, three particle materials, plumes, bolts, flocks, wind streaks, polylines, panels, billboards, bitmap and SDF text, insets. **Rain ships, as streaks rather than sprites**: `RainField` fills a `LineSegments` with a slab of drops that follows the viewer, each drawn from where it is to where it was a shutter-time ago, so the streak runs along the velocity and a gust leans every drop at once with nothing trigonometric. A round sprite stretched by its motion would have wanted a new attribute and a branch in both particle programs; a segment says it with geometry that already ships. It reads no clock and no random number — a drop's column is a hash of its index and how many times it has fallen — so a consumer evaluating instants out of order gets the same rain every time. **Drops land on the ground and do not fall through roofs**, both from the surface seam rather than from anything the rain owns: a roof is the nearest floor under anything above it, and `coveredAbove` asks whether the surface has a face overhead. **A hole is a hole for free** — a gap between pads, a ribbon's `holes`, the edge of a bounded field — because the answer is the geometry's own and cannot disagree with the opening it was cut from. `coveredAbove` is the general query and rain is one caller: a puddle that forms only where the sky reaches, a shaft of sun that should not be indoors, and an agent deciding to take shelter are the same question. **The fall speed moves while the field runs**: `speedMps` and `streakSec` were `private readonly`, so a weather state that changed under a player could not change the rain. Reported from outside by a consumer whose hailstorm — 14 m/s against rain's 9 — had to be expressed as a wider, denser rain and read as heavy rain. Both are plain fields, because nothing is sized by either and nothing caches a value derived from one. Driven by `demo/dev/lines.html`, whose roof has a gap in it and whose `?rainspeed=` is written every frame, so a field reading its speed once at construction draws the wrong streaks **A stroke can say it is light, 3.43.0**: `drawLines` takes a blend, so a glowing outline is one additive pass rather than two alpha-blended ones faking a halo. It is a blend and not a bolt mode, which `AGENTS.md` forbids — what separates a line from a bolt is the path, a bolt jitters because it is lightning, and an additive line still follows the path it was given and is still fogged. | **Animation** | **Clips and skeletons ship in `@driftengine/animation`**, and nothing draws with them yet. `Skeleton` resolves a `Pose` — three flat arrays, not an array of objects — into a skinning palette written in place, and refuses a hierarchy that is not sorted parents-first rather than producing a rig wrong in one limb. **Skinned shadow casting shipped** and is the one capability this row lost without the sentinel noticing; see §5. `sampleClip` is **a pure function of a time the caller supplies**: no clock, no `Math.random`, wrapping rather than clamping and correct for a negative time, holding at a track's ends rather than extrapolating, and taking the shorter arc between two rotations on opposite hemispheres. That last one is asserted by a test that had to be rewritten to assert it — the obvious pair of keys has a dot product of exactly zero, so the hemisphere flip never fires and the first version passed with the correction deleted. **Rigid TRS ships too**: `RigidAnimation` drives `SceneNode`s from a clip, so a door, a lift or a turntable animates with no shader change at all — and it calls `markMoved`, without which a node moves on the first frame and freezes on the second, because a fresh node is dirty already and nothing marks one that was written in place. **The skinned vertex shader is built and generated, and nothing selects it yet.** `MeshData` carries `joints` and `weights` as two more optional attributes at locations 11 and 12, `setSkinPalette` uploads a palette into a vertex data texture on both backends, and `flatVert` is a two-variant permutation whose skinned arm reads that palette with an integer fetch. **A permutation and not a uniform gate, measured: 1,118 bytes gzipped against the 246,925 one more fragment flag costs**, because the vertex shader had no permutation axis at all and two 4.4 KB strings mostly dedupe inside deflate's 32 KB window — so the 2^n rule in `ARCHITECTURE.md` §1 is a fact about the fragment corpus rather than about permutation. **Both backends select it per draw**: a rigged mesh takes the skinned pipeline and an unrigged one does not, so a scene holding characters and walls draws both correctly. WebGL2 compiles a second flat program lazily on the first rigged mesh and feeds it the whole frame's lit state — a uniform location belongs to a program, and an unwritten uniform is zero, which is the failure this engine has recorded twice; WebGPU carries the flag through the pipeline key, the bind group layout and the bind group together, because a skinned module against an unskinned layout validates, draws and is wrong. **Every published scene is 0 pixels of 921,600 on WebGPU, all seven**, against a before-and-after pair captured from two servers in one run. **Driven and compared**: `demo/dev/skinning.html` bends a two-joint bar beside an unrigged control, and rest against bent moves **22,608 pixels of 832,000 on both backends**, which agree **to the pixel** at either phase. The palette takes texture unit 11 and not 0 — `MAX_VERTEX_TEXTURE_IMAGE_UNITS` and `MAX_TEXTURE_IMAGE_UNITS` bound the two stages separately but do not number their units apart, so a palette at unit 0 lands on the directional shadow map and the driver answers `two textures of different types use the same sampler location`. Found on hardware on the first capture, which is what a capture is for; WebGPU never had it, its bindings being per bind group. **glTF imports a rig**: `readGltfSkins` reads skins and animations, sorts joints parents-first — which only the importer can do, since every index naming a joint has to move with them — and remaps a mesh's `JOINTS_0` and every animation channel onto that order. **Flattening stays the default and a skin is the one exception**: a skinned primitive keeps its vertices in model space, because a palette entry already places them and baking the node's world matrix in as well throws the rig across the scene. A document with no `skins` takes the path it always took. Weights are normalised on the way in, warning per mesh, rather than divided per vertex per frame; a vertex carrying no weight at all is left alone and reported, because inventing an influence would move geometry nobody rigged. **The container carries a rig at 1.6**: `SKIN` holds joints, parents and inverse binds; `ANIM` holds a clip per chunk; and **`NODE` is finally written** — specified in `FORMAT.md` §4.3 since v1, with no writer and no reader for the whole of it, until rigid TRS needed a hierarchy. All three are optional, so a 1.5 reader opens a 1.6 file as the geometry it also holds, which is rule 2 doing its job; §4.4's own example of a free additive change was a file carrying `ANIM`, and it stopped being hypothetical. The skin is written parents-first and the **reader** refuses any other order, because a palette is resolved in index order. **End to end**: `bake` writes the rig a glTF carried, `streamDrft` reports `onNodes`, `onSkin` and `onClip` as their chunks land, and `DrftLoader` hands all three on. That last one is asserted rather than assumed — the normal-map texture index was written, carried and readable for a whole release while the loader was the single layer that discarded it, invisible to every test of either side because both sides were correct. **And it carried half of one until 1.11.** `SKIN` was correct from the day it shipped and the _per-vertex_ half it points at was never written at all: `MeshData` declared `joints` and `weights` and `validateMeshData` checked both — four floats a vertex, and neither without the other — while `buildMesh` listed the optional arrays it had bits for and there were none for these. **The write succeeded in silence**, which is the whole of why it survived four minor versions: a baker handed the writer a correctly-validated skinned mesh, got no error, and produced a file carrying a skeleton, its bind pose and its clips pointing at vertices that recorded no influence on any of them — and `Mesh.isSkinned` reads `data.joints`, so what came back drew in bind pose for ever. A consumer wrote its own binary container for one human body rather than use this, about seventy lines across a baker and a loader. Every other layer was already right: the glTF reader reads `JOINTS_0` and `WEIGHTS_0`, the weld's attribute table carries them, and both backends upload them at attributes 11 and 12. `ATTR_JOINTS` and `ATTR_WEIGHTS` are the next two free bits, appended last, so a 1.10 reader meets the seven arrays it knows in the seven places it expects them and draws the asset in bind pose. **The round-trip test that should have caught it was right and its fixture was not**: it enumerates the keys of the mesh it builds and reports every loss at once — the method `relief` bought — and the mesh it built carried no influences, so there was nothing to enumerate. The fixture carries them now. **And `.fbx` carries a rig too, which is the format most of them arrive in.** `readModel` documented `skins` and `clips` as "glTF does; nothing else here does", and FBX is how characters are _sold_ — it is the only thing Mixamo exports — so the one format a bought character comes in was the one a rig could not be read from. A Renderpeople figure measured through this reader gave a bag of triangles with no skeleton, no weights and no clip; the same file converted to glTF first gave 88 joints and a 64-track take. **The bind pose is the bone's transform undone and the mesh's applied**, and where each half comes from is what 3.40.0 got wrong and a later release corrected. A cluster carries `TransformLink`, where the bone was when the mesh was bound, and `Transform`, which the SDK documents as where the _mesh_ was — so `inverseBind` looks like the inverse of the first times the second. **Exporters do not write that field that way.** `Transform` is a property of the mesh and would be one matrix for the whole skin; measured on a bought character, **sixty-eight of its sixty-nine weight-bearing clusters disagree about it**, each holding something close to the inverse of its own `TransformLink`. Composed as documented, the bone's frame goes in twice: that character's hip came back as a pure translation of `(0, -94.4, +94.4)` where the joint is at `(0, 94.4, 0)`, so inverting it put every joint on a mirror of the skeleton that no geometry occupies, and one hand landed on the origin, which no bind pose contains. The mesh's half is taken from the node graph instead — the one authority this reader already has for where anything is, and the same walk every static mesh goes through. **The check that finds this is worth keeping**: invert a joint's bind matrix, take the translation, and compare it against the centroid of the vertices that joint dominates. On a correct rig they agree within a limb's own length; here they disagreed by up to 1.77 m, and afterwards by at most 0.35 m, which is a femur. **A bone names its cluster and its parent bone, and only one of those is hierarchy**: the transform walk took whichever the exporter wrote first, and a cluster is not a model, so a prop parented to a hand drew as though the hand were a root. Weights are normalised on the way in and a vertex held by more than four joints keeps its four _largest_, both said once per mesh. **Rotations are the chain and not the curve**: FBX composes a joint's local rotation as `PreRotation * R * inverse(PostRotation)`, both of the outer terms fixed per joint and written on the model rather than in the curve, so a reader taking the curve alone plays a take in which every joint carrying one is turned by a constant amount — **twenty-nine of this character's eighty-eight**. Every key still interpolates and the clip still runs, which is why it reads as a bad export rather than as an unread field. A non-default `RotationOrder` is the one part of the chain still refused by name. **And a binary FBX separates a name from its class with `\0\x01`, not with `::`** — the ASCII form's separator is the one a reader tends to be written against, because it is the one the specification's examples show, so every joint came back as `…_spine_01\0\x01Model` and the take as `Take 001\0\x01AnimStack`. Nothing fails on a name: `Joint.name` is what retargeting matches on, so a rig whose every joint carries a class suffix matches nothing, one subsystem away from the reader that wrote it. Both were found on real bytes, which is what real bytes are for. **And the geometry stopped arriving five times over.** The reader wrote `indices[i] = i` across every corner it had fanned, so a bought character came back at 64,518 vertices where its own file describes 12,216 — the baker welds, so a baked asset never showed it and anything calling `readModel` directly carried all of it. Deduplicating on the layer _offsets_ is the cheap answer and shares almost nothing, because an exporter writing `ByPolygonVertex` `Direct` gives every corner its own offset into repeated values: measured on a rigged car, 1,958,002 vertices of 1,958,016 corners, fourteen shared out of two million. Keyed on the values instead, bucketed by control point, the same car is **388,362** and the three FBX files in this repository come down by 4.2 to 5.0 times — and the read is **three and a half times faster**, 827 ms against 2,952 ms, because the allocations went with the duplicates. What is still absent: materials and textures are unchanged, morph channels driven by curves are not read, only the first animation layer of a stack is, and the `Take` records of pre-7000 files are not. **Measured on the character it was written for**, a 24.6 MB Renderpeople figure at version 7300: 12,216 vertices and 21,506 triangles — the same vertex count the file gives through a glTF conversion — 88 joints named and sorted parents-first with no joint naming a parent after it, a 176-track take of 2.267 s, every joint index in range, no vertex left unweighted, and weights summing to one within 4.5e-8. Baked to `.drft` 1.11 and read back it is the same asset, and the engine's own `Skeleton` accepts the rig and resolves an identity palette at the bind pose to 2.7e-5 over the whole 88-joint chain. **That last figure is not evidence of much, and saying so is the point**: it derives the pose from the inverse binds themselves, so it was equally green while those matrices put every joint on a mirror of the skeleton. What caught that was comparing them against the geometry, which is a different question and the only one that could have. **Units are read too**: `GlobalSettings.UnitScaleFactor` counts centimetres per file unit, so `unitScale` is that over a hundred, and a consumer scaling a bought character no longer divides by a measured height, which is a guess dressed as arithmetic and is wrong for anything that is not a standing human. **The two rig-specific exports that ship beside it are not a reader fault**: `_ue4.fbx` and `_u3d.fbx` carry 95 and 88 `LimbNode`s with their curves and **no `Geometry` records at all**, so they are animation-only files and the refusal was correct — it just could not say so, and now it counts what it found and names which of the three shapes of nothing it met. `fbxHarness.ts` writes the binary records a test needs, because the files that would prove this on real bytes are licensed character assets that cannot be committed here. **The graph over clips ships**: `blendPoses` and `addPose` — additive being a _delta_ rather than a target, so translation adds, rotation composes and scale multiplies — `BlendTree` over a two-way lerp and a one-dimensional set, and `AnimationStateMachine` with crossfaded transitions. **Both take a bind pose**, and that is not optional in practice: `sampleClip` leaves a channel no track mentions as it found it, so a rotation-only clip preserves the pose it was given — but `blendPoses` interpolates _every_ channel, so a tree whose scratch poses start at zero translation collapses every joint onto its parent's origin the moment it blends anything. The failure is a figure folded in on itself rather than an error, and it was found by building `demo/character.ts` on the API and looking at the result. Every layer is a pure function of a caller-supplied step: a state machine is where an engine most naturally reaches for a clock, because a fade has a duration, and one here would end the replay story. Parameters are the consumer's own strings throughout. A fade in flight is not re-evaluated against the condition that started it, or a transition would stutter wherever its parameter sat on the threshold. `setJoint` writes a joint directly, which is what Track B's ragdolls need from a pose. **Two-bone IK ships**: `solveTwoBone` is closed form rather than iterative, because two bones and a target are a triangle and a triangle has an answer — and a solver whose result depended on how many iterations were run is a solver a replay cannot use. An unreachable target straightens the chain toward it, which is what a limb does. **The order is the non-obvious part**: the mid joint is bent first, because rotating the root turns its whole subtree and so changes where the chain points and never how long it is — bending the root first leaves the tip on the right ray at the wrong distance, measured as 1.22 units where 1.00 was wanted. The pole hint then decides the one thing the target cannot, which way the elbow faces, and it is applied as a roll about the line to the target after aiming. `Skeleton.world` is public for solvers and attachments, since a palette entry is a world matrix times an inverse bind and is useless to anything asking where a joint _is_. **Morph targets ship on both backends**: deltas belong to the _mesh_ and weights to the _draw_, so two characters sharing one head mesh wear different expressions without a second copy of the geometry. They ride the vertex data texture the joint palette established — which is why the row was affordable, since eleven attribute locations were already spoken for and glTF morph wants up to twenty-four more. **Morph is applied before skinning**, because a target deforms the bind pose and the skeleton then carries that shape; the other order makes an expression drift as a limb moves. Measured on hardware: the bulge moves **16,733 pixels of 832,000 on both backends**, which agree to the pixel with morph on and off. **And they import**: glTF's targets are read and transposed to be interleaved by vertex, which is a transpose of how glTF stores them — one accessor per target there, all of a vertex's targets adjacent here, because the shader fetches them together. A file with more than eight keeps eight and says which it dropped, since a facial rig routinely carries dozens and refusing it serves nobody. The container carries them as **`MORP` at 1.7**, and the mesh ordinal is in the payload rather than the chunk table's `index` — that field is the ordinal _within a FourCC_, so for a file where only the second mesh has targets a reader pairing by it would deform the first. What is absent: **morphed normals** — positions only, so shading lags a strongly morphed surface — **Retargeting ships**: match by name, transfer rotations, and leave the target rig its own bone lengths — two rigs of different proportions share joint _orientations_ and not lengths, so copying a translation puts the taller one's limbs inside its own body. The root is the exception, because that is where locomotion lives. Matching is **exact and there is no name database**, for the reason the gamepad layer ships none: a table of synonyms rots silently and its failure is a limb that does not move. Unmatched joints are _reported_ rather than acted on, since whether one is a broken import or a simpler rig is a product decision. What is absent: **no joint limits, no twist, no chains longer than two bones, and no retargeting between different topologies** — a split spine playing a single-spine clip needs a decision about distributing the rotation, and that belongs to whoever knows what the character is. **Root motion ships**: `extractRootMotion` answers how far the root travelled between two sample times and `stripRootMotion` pins the pose's root to the clip's value at time zero, so the caller moves the character and the pose does not. **Loops are accumulated rather than subtracted**, which is the whole difficulty and the thing a naive version gets wrong invisibly: sampling the root at both times and subtracting answers a full stride _backwards_ every time the clip wraps, because the root snaps from the end of the cycle to the start of it. So the interval is split at every loop boundary it crosses and the pieces composed — asserted by a test whose expected value is +2 where the subtraction answers −2. **The delta is in the root's own frame at the earlier time**, so a caller applies `position += worldRotation * delta` and a character that has turned walks along its own forward axis; the rejected convention is a delta in the clip's space, one subtraction shorter, which drags every turned character sideways. That choice is asserted by a clip whose root faces ninety degrees about Y, where the two conventions answer `(0, 0, 2)` and `(2, 0, 0)` and nothing else in the suite can tell them apart. It stays a pure function of the clip and two times, reads no clock, and writes into a caller-owned target; the interpolation is `sampleTrack`, split out of `sampleClip` in the same commit so root motion reads the same decision rather than a second copy of it. What it gives up: **a vertical bob authored on the root leaves the pose along with everything else**, so a caller whose height is owned by a physics controller ignores the y component and the bob is then in neither the pose nor the position. What would make that wrong is a consumer wanting per-axis control, and the answer then is a mask on the extraction rather than a second convention. Bound to DriftScript as `animation.rootMotion` and `animation.stripRoot` with a `Motion` opaque, and **both descriptions say to pair the two calls**, because a script that extracts without stripping moves its character at exactly double speed with nothing failing. **The clause that once close this row was left standing through four commits that falsified it** — it read "no blending, blend trees or state machine; no IK, morph targets, root motion or retargeting; and the container carries none of it", each of which the paragraphs above now describe shipping, and one of which the same sentence had already contradicted twice. A row long enough to accrete is a row that needs reading end to end before it is added to. `cinematic/` moves cameras and nothing else. |

| **Physics**   | `physics/` is **kinematic convex collision**, swept per axis: `boxShape`, `sphereShape` and `hullShape` build a `ConvexShape` — the last from any point set, with an optional radius that rounds it — `colliderFromShape` gives the broad phase its bounds, and `ColliderSet` hashes them spatially. **Cloth** is XPBD: distance and bending constraints with compliance, so stiffness stays meaningful as the iteration count changes — the same property soft constraints were chosen for. It is a separate solver from the rigid bodies deliberately, because thousands of rotationless particles are the wrong data layout for a rigid constraint graph. **Two-way coupled, by an impulse exchange rather than by a merged island** — and the refusal this replaces was right about the price and wrong about the only way to pay it. Putting particles into the rigid solver's constraint graph _would_ merge islands, and merged islands are what the parallel executor is made of, so that stays refused. What ships is the exchange the two solvers can make without either learning the other's structure: the collision pass already moves a particle out of a body, a particle moved by `d` in a tick of `h` has had its momentum changed by `m·d/h`, and the body receives the opposite **at the contact point** through the same `applyImpulse` any consumer would call — so a sheet landing on one end of a plank tips it, which an impulse through the centre of mass could not. **Explicit, so the body answers on the next tick**: it is a spring with a one-tick delay in it, and a very heavy sheet on a very light body rings. `coupling` is a scale from 0 to 1 and **0 is the default**, so no existing world moves until it asks; `particleMass` is in kilograms and is separate from `invMass` on purpose, because that array is a relative weight the compliance is tuned against and redefining it would move every sheet anybody has tuned. Asserted against the same world with no sheet in it, which must agree exactly at zero. **Self-collision ships the same day**, and it is off by default for the reason its own tuning is the hard half: `selfDistance` in metres, a spatial hash rebuilt each tick with one bucket a particle, a 3×3×3 cell scan, and a symmetric push apart split by inverse mass. **Particles a link joins are exempt**, built once as a CSR adjacency — not an optimisation, since a stretch link's rest length _is_ the spacing and a self-collision distance anywhere near it would have every neighbour fighting its own link and the sheet would inflate rather than drape. A projection rather than a compliant constraint, because a contact is an inequality and XPBD's accumulated multiplier is for something that holds all tick. **Measured on a sheet squeezed until it folds**: with it off the closest unlinked pair comes to **58 mm** inside a sheet whose own spacing is 100, and with it on the closest pair is at or above what was asked for at 60, 80 and 90 mm. **Bending resists bowing rather than orientation**, which is a property of a skip-one distance constraint rather than of the tuning: three collinear particles satisfy it at any angle, so it will not hold a cantilever out. Measured, and said where the links are built. **And for a while it could not be drawn**, which is the shape of gap a capability list is worst at showing: cloth shipped in 2.9 and `RendererApi` had `createMesh`, `drawMesh` and `disposeMesh` and no way to rewrite a vertex — so a deforming surface could only be drawn by recreating a mesh every frame, which is a GPU buffer allocation per frame, or by splitting it into rigid quads with a matrix each, which caps the resolution at the number of draw calls a consumer can afford. `updateMesh` closes it: positions and normals only, because colour and emissive describe what a surface _is_ and do not change because it bent; the vertex count is fixed, because the index buffer and the pipeline are sized against it; and a mesh says `{ dynamic: true }` at creation, which decides a buffer hint on WebGL2 and, on WebGPU — where every attribute interleaves into one buffer and a position cannot be patched without the rest of the vertex — whether the interleaved array is kept at all. **Found by a consumer trying to hang a banner**, which is the only way a row like this gets found.

**Six sentinels, four fired and two did not, and the pattern is now legible.** `rigid-body-dynamics`, `joints-constraints`, `world-raycast`, `vehicles` and `cloth` named a class or a symbol the implementation was always going to have. `triggers` named `sensorEvents` and `ragdolls` named `ragdollFromSkeleton`; what shipped was `BODY_SENSOR`, `ContactEvents`, and `ragdollFromBones` — the second forced by the package boundary. **A sentinel naming a plausible class survives the guess; one naming a function is a guess at a name, made before the code exists, which is the worst moment to make it.**

**A character controller and ragdolls ship.** `CharacterController` is a kinematic capsule sweeping the same world every query does: sweep-slide-project at a fixed pass count, step-up under a height limit, slope classification, and a push into dynamic bodies that carries the character's _speed_ rather than its per-tick step. Its feel is on it too — acceleration, air control, variable jump height, slide boost, and **coyote time and jump buffering counted in ticks** rather than accumulated in a float of seconds. `AGENTS.md`'s worked example for the engine/game boundary is corrected to match its own audio rule: the mechanism and its parameters are engine, and which numbers you choose is game. **There is no ground snap**: it was built, measured at a _worse_ foot gap than none — 0.490 metres against 0.457 descending a sharp forty-degree crest — and removed, with the instrument that would justify bringing it back written where it stood. **A ragdoll's joint limits are per joint**: `swingCos` and `twistSin` were one pair applied to every joint a rig has, and a knee is a hinge with no twist where a shoulder is nearly a ball — so a consumer chose which of the two to get wrong. Reported from outside, where the choice was loose (a 78° cone and 74° of twist everywhere) and what it produced was reported from play as _a scrambled ball of things, limbs torso head mixed together_: at 78° nothing stops a knee folding a limb through the torso, so a body that lands knots itself. Either option now takes an array indexed the way `parents` is, with the default standing in past its end and wherever an entry is not a finite number — because the other reading of a missing entry is zero, and zero is a 90° cone at the joint nobody thought about. What it does **not** buy is a real hinge: a narrow cone still bends a little in every direction, and the axis a revolute joint would need is rig data this builder is never handed.

`ragdollFromBones` takes **plain data** — a parent array and a flat array of joint world matrices, which a skeleton already exposes — and writes back through a structural target that an animation `Pose` satisfies exactly, so neither package imports the other. One capsule per bone, cone-twist jointed to its parent's, masses from bone volume, and `drive` steers toward an animated pose rather than replacing it, which is what makes a hit reaction rather than a body going instantly limp. **The joints are anchored at the bone ends they share, and were pinned through the middle of the bone before that**: a knee is not the middle of a shin, and anchored at the child's centre the shin turns about its own middle inside its cone, so the knee end of the shin walks away from the knee end of the thigh. Reported from outside at 56 to 100 cm open in flight; the test that sees it measures the two ends that share a joint, because every body is still exactly one bone from its parent's _centre_ either way. **Bones that share an end no longer collide either**, since two capsules jointed end to end overlap by construction and that contact fights the joint holding them together; `selfCollision: false` switches off all of it, and is measurably worse, because the cones alone do not stop a foot reaching the ribcage.

**The `ragdolls` sentinel did not fire either, which is the sixth.** It named `class Ragdoll|ragdollFromSkeleton`; what shipped is an _interface_ `Ragdoll` and `ragdollFromBones`, because §2 forbids importing the package `Skeleton` lives in. Two guesses in one track, both made before the code existed, both green over capabilities that had arrived.

**Joints, queries and sensors ship.** Six joint types — distance, spherical, revolute, prismatic, fixed and cone-twist — each with its rows unrolled rather than one configurable 6-DOF joint, with motors, one-sided limits and a breaking threshold, solved before contacts in the same substep loop because a joint is structural and a contact is transient. **No angle appears anywhere in them**: a swing limit compares a dot product against a stored cosine and a twist limit compares a quaternion component, which is what the solver wanted anyway since it clamps rather than measures. `raycastWorld`, `shapecastWorld` and `overlapWorld` fill caller-owned buffers and allocate nothing, and a ray starting inside a body reports that body at fraction zero rather than nothing. A **sensor** runs narrowphase and skips the solver, and `ContactEvents` drains enter, stay and exit into a caller-owned buffer _after_ the tick, ordered by pair key — never callbacks during the solve, which would both invalidate the indices the solver holds and break the executor.

**A seventh joint type ships, and it is a refusal narrowed rather than reversed.** `joints.ts` refused a configurable 6-DOF joint in its own header, on the ground that a generic joint is a constraint set decided at runtime — a branch per row in the hottest loop in the engine, and a megamorphic call site above it. That argument still stands and nothing here has changed: the six keep their own arms, their own rows and their own numbers, and **none of them gained a branch**, which the joint tests already there assert by staying green alongside the determinism gate. What the refusal named as its own cost was that "the package has to grow a type", and that is exactly what arrived: `JOINT_SIX_DOF` is a seventh arm above the chain rather than a runtime configuration the other six go through, so the branch a six-DOF joint pays for is paid by six-DOF joints and by nothing else. Three linear and three angular degrees, each **free, limited or locked**, in **body A's own frame** — not a frame of the joint's own, which costs a caller wanting other axes an orientation on A and would be reversed by four more floats per joint. **The mode is explicit rather than inferred from the bounds**: the widespread convention that `lower > upper` means free needs no extra field and turns a caller who swapped two numbers into a joint that silently does nothing, where a mode byte cannot be mistyped into the wrong meaning. Locked is **zero**, so an undescribed joint is rigid rather than one whose bodies fly apart. **It solves six independent scalar rows rather than two coupled 3x3 blocks**, because the blocks would not exist — a caller leaving linear y free and locking x and z has a 2x2, and the next caller has a different one — and the cost is measured: an all-locked six-DOF joint is softer than `JOINT_FIXED`, so the type's own comment says to reach for the fixed one when all six are locked, and a test asserts the two agree to within a millimetre rather than exactly. Angular bounds are **sines of half angles**, this package's own unit, because `Math.acos` and `Math.atan2` are both on the banned list. **It has no motor and says so on the console at `add`**, once per process, rather than accepting one and never driving — a motor asked for and silently not delivered reads as a broken motor rather than an unsupported one. It costs **1,391 gzipped bytes, 4.6% of the package**, which is what an unrolled solver looks like when the thing it unrolls is a configuration rather than a shape. **Not reachable from DriftScript**, and neither are the other six: `drift/physics` binds bodies, contacts, queries and forces and has never bound a joint, though its own header once said "joints" — see §4.

**The `triggers` sentinel never fired, and that is the fifth time this document has recorded that failure.** It was added naming `sensorEvents|class Sensor`; what shipped a commit later was `BODY_SENSOR` and `ContactEvents`, so the guard sat green over a capability that had arrived. A sentinel is a guess at a name, and a guess made before the code exists is a guess made at the worst moment — the two that _did_ fire here, `joints-constraints` and `world-raycast`, were written when the shape of the answer was already known.

**`StallEscape` ships**: a kinematic body that has stopped making progress, and the cheapest way out of it. A character controller resolves a move against geometry and has no opinion about a body that has been asking to move for half a second and going nowhere — which is where players get stuck, and where a consumer meeting it for the first time gets it wrong in the same order everybody does. Progress is a question about **net travel over a window**, never this tick's displacement, because a body jammed under a low ceiling _jitters_ by thirty times any per-tick threshold while sitting at the same coordinates. A body that is **grounded, supported and has headroom is not stuck** — three separate facts, and the first two differ exactly where a fall was arrested on a contact no rule calls support. A direction the world would refuse is not an escape route, so an `EscapeVeto` is taken structurally, the same shape `GroundProbe` is and for the same reason: a consumer with an analytic surface has a second authority about where a body may be, and a deck edge carrying no collider at all reports clear air to a probe that asks only the colliders. Horizontal wins over vertical by a wide margin, because being eased upward reads as levitating and slipping sideways reads as slipping. And **sealed is reported, never acted on** — the engine says there is nowhere to put the body, and what that costs a player belongs to the consumer. Every rule in it was paid for in a shipping game, and the entry point is 322 lines of them.

**A 32-layer mask ships with it** — thirty-two rather than sixty-four because a JavaScript bitwise operator is 32-bit — and a pair interacts only where each side's mask holds the other's layer. **And two named bodies can be excluded outright**: a mask says what a body _is_, so it can express "this kind does not meet that kind" and cannot express "these two in particular", which is the whole of what a ragdoll needs. `world.ignorePair(a, b)`, with `allowPair` and `pairIgnored` beside it, is the second question, and it is followed through a removal because a body index is a slot and not an identity. A world that never calls it pays one integer compare per candidate pair. **An elliptical friction cone ships, and it is off by default.** The two friction rows were each clamped to `mu * N` on their own, which is a **box**: along the diagonal between the two tangent axes the pair reaches `sqrt(2) * mu * N`, forty-one per cent more grip than the same surface offers along an axis — and the tangent basis is built from the contact normal, so _which_ headings are cheap is an artefact of that construction rather than a fact about the world. **Measured**: a box launched at 4 m/s over eight headings travels **1.064 m along the axes and 0.737 m along the diagonals, a ratio of 1.46**; under the ellipse it travels 1.059 to 1.073 m, a ratio of **1.013**, and the longest distance is unchanged, which is the control that says the ellipse did not simply weaken friction. **`frictionModel: 'elliptical'` is a world option and `'box'` is the default**, because every stacking result moves under the ellipse: `fingerprintBodies`, both baselines, and any golden fingerprint or stored replay a consumer has kept. A production engine does not silently invalidate those; _what would reverse it_ is a major version, where the honest thing is to make the ellipse the default and say so in the porting guide. **One coefficient, not two**, so the ellipse is a circle: anisotropic friction is the natural API for an ellipse and it needs a tangent frame anchored to a _material_, where these tangents rotate arbitrarily with the normal — a per-axis coefficient over them would mean something different from one tick to the next, which is a silent wrong answer. _What would reverse it:_ a tangent frame carried by the body, which is a larger change than the cone and which `vehicle.ts` already answers its own way with a grip table. The coupled solve also reads **one** relative velocity for both rows where the box path re-reads it between them, which is a second reason the numbers move and is why there is no version of this that a stored replay survives. **A static concave mesh collider ships.** `meshShape(positions, indices)` builds the triangles, their planes, an edge classification and a `DynamicTree` over them — the tree this package already has, built once and never moved, so no second acceleration structure had to be written or tested. **Static only, and the limit is enforced rather than documented**: `addBody` refuses a mesh on anything but a static body and `colliderFromShape` refuses one outright, because a moving concave mesh needs its tree refitted every tick and a mass tensor a triangle soup does not have, and because a mesh handed to the kinematic sweep would arrive as its own bounding box and turn a hollow level into a solid brick. **Every triangle goes through `collideShapes` unchanged**, as a three-point polytope written into one scratch shape — so the separating-axis test, the clipping, the sphere and capsule paths and the cylinder's own module are all exact against a mesh on the day it lands, and none of them was written twice. What that costs is the moving shape transformed once per candidate triangle rather than once per pair. **A mesh pair fills a _set_ of manifolds where every other pair fills one**, because a body in the corner of a mesh room has two or three contact planes and reducing them to one picks a wall and lets the body through the others. The solver already supported it — `prepareContact` appends — and `storeWarm` now accumulates by pair rather than replacing, with the triangle folded into every feature id so a box on a seam stops handing one triangle's impulse to another. **One-sided**, because a level mesh is a surface rather than a solid and a two-sided triangle fires anything that has sunk below it back out the wrong way. **And the interior-edge filter is the half that decides whether it feels right, measured rather than argued.** A box sliding across coplanar triangles meets their shared edge, where the narrow phase finds an edge normal and shoves it backwards — a character stumbling on a flat floor once a metre. Each edge is classified once at build time as convex or not, and a normal off a non-convex edge is replaced by the face's with the separation recomputed from the face plane. **A box slid at 6 m/s across sixteen quads keeps 80% of its speed with the filter and 1% without it**, which is the number the row's own note predicted and nobody had. Rays are two-sided, by Möller-Trumbore against the same tree, because a sight line that saw through a wall from behind is a worse answer than one that did not. **Convex decomposition ships, and with it the compound body that gives its output somewhere to go.** `decomposeConvex` is offline: it voxelises a triangle soup, floods the outside to find the interior, claims maximal boxes of solid cells, merges them, and returns at most 32 hulls of at most 50 points each — inside `hullShape`'s cap of 64. **A grid rather than the triangles**, because a collision mesh is routinely not watertight and every method that reasons over the source has to decide what its inside is; a flood answers that once, the same way, for any input, at a cost set by the resolution rather than by the triangle count. **The merge is measured two ways and that is the design.** Reaching the part budget takes thousands of merges, ordered by how empty a merged bounding box would be; going below it takes a handful, and each asks how much of the merged hull is not solid. **A box cannot tell a convex solid from a cavity**, and three attempts to make it were each wrong differently: a fixed threshold on box emptiness left a convex prism as **eight parts**, because a cylinder's box is 21.5% empty however it is cut; scoring the change against the sum of the parents gave negative costs that always pass and collapsed a cup to one hull at **403% bloat**; anchoring against the emptier parent let each merge license the next and reached **57%**. A real hull costs 1.09 ms at fifty points and is affordable at that count because a region is always a union of boxes, so its support set is exact from its seeds' corners and needs no walk over cells. **And greedy pairwise merging cannot finish a slanted convex solid either**: a tetrahedron came back as sixteen parts at 20.3% bloat, because every individual merge across a staircase leaves a notch while merging all of them is free — so the whole solid is tested for convexity once, before anything is merged, which is the case a crate, a wedge, a rock and a wheel are all in. **The defect that cost the most to find was in the fill.** A face lying exactly in a cell boundary plane is tangent to the cells on both sides, so the plane test compares two quantities equal in exact arithmetic and differing by a rounding step in this one; when it fell the wrong way _neither_ cell was marked, the flood walked out through the base and the interior came back empty. Measured on a closed 24-sided prism of true volume 3.106, the fill answered **3.57, 0.56, 0.47, 3.37, 3.33, 3.31, 0.20 and 0.17** at resolutions 32 through 96 — correct at four and the bare shell at four, with nothing in the shape to say which. The cell box is grown by one part in a million, which is the safe direction: a spurious cell costs a little accuracy and a missed one is a hole. **It was visible only because the check sweeps resolutions**, since a leak deflates the source volume and the hulls together and every bound held at any single one. Measured by `npm run check:decompose`: a convex prism returns one part, an L-beam two at zero bloat, a cup 12 to 14 with its cavity open, a staircase 4 to 6. **A torus is the honest limit** at 27.0% summed and 16.2% occupied — the gap is overlap counted twice — and the budget is not what binds it, since the same torus measures 26.7% at eight parts and 20.6% at thirty-two and reaches the same figure with the merge's tail switched off; `docs/IMPROVEMENTS.md` carries what would improve it. **`BodyDesc.shapes` is where the hulls go**, and it had to exist: `BodySet.shape` held one shape per body, so this row's own refusal message — _"convex decomposition into hulls, which the runtime already accepts"_ — was true of the kinematic sweep, which has taken `Body.parts` all along, and false of the dynamics it was written in. A part carries no offset and no rotation, because a `ConvexShape` is already a point cloud in the body's frame. Mass is `combineMassProperties`: volumes added, the centre volume-weighted, each tensor moved by the parallel axis theorem — **overlap is counted twice and that is the decision**, since removing it exactly is a boolean intersection of convex solids correcting a number the caller invented when they chose a density. Contacts are one manifold per touching part in a set sized to `MAX_BODY_PARTS`, so a compound against a single convex shape can never overflow, with the part pair folded into every feature id the way `meshContact` folds a triangle index. **`compound × mesh` shares the manifold budget between the parts that find candidates, never below one each** — a departure from the mesh path's first-come rule, which is defensible when the ninth candidate is a triangle and indefensible when it is a limb. `addBody` refuses a body carrying both `shape` and `shapes` or neither, an empty list, more parts than the cap, and a mesh as a part. **Two of the four mutations run against these claims survived the first version of the tests**: handing the whole mesh budget to the first part passed a settled body's tilt, because the simulation reaches a lopsided equilibrium anyway, and removing the feature-id fold passed everything, because two identical parts carrying identical loads are exactly where swapping their impulses shows nothing — both are asked of the narrow phase directly now. **The container carries the result as `COLL` at 1.12**, a FourCC claimed in v1 with no payload, no reader and no writer until this row decided what a baked hull is: a set of convex hulls, as points, because `@driftengine/drft` depends on nothing. `drft bake --collider hull[:N] | box | none` writes it and prefers a vehicle folder's `collider.kn5` over the model's own geometry. **`physics-only` did not move, and that took a correction**: `MAX_BODY_PARTS` was declared beside `decomposeConvex`, and importing one integer from an offline module put the whole voxeliser into every bundle touching physics — a named import of a `const` is enough to defeat tree shaking across a module boundary, and an A/B on that line is what said so. **What is still absent** is a worker pool behind the island executor's seam. Each names a sentinel or a refusal on record. **The worker pool is measured and still absent, and the seam's own comment named the wrong quantity.** It said "a pool is slower than serial below some body count"; a pool splits _islands_, so a world with one island has nothing to split however many bodies it holds — `islandParallelism.test.ts` pins that with a hundred jointed bodies solving as one island, and `packages/physics/scripts/island-bench.ts` prints the numbers. Measured on a 24-core desktop: the island solve is **58% to 76% of a tick**, so Amdahl caps any speedup at about 2x to 4x before a worker starts; one island of ten boxes is **160 to 185 microseconds** and the hundred-body single island is **1,129**; and a fork-join over a `SharedArrayBuffer` costs **6.8 microseconds at one worker, 11.8 at four, 23.7 at eight** with no work in it — half of one per cent against 2.6 milliseconds of solve at sixteen islands. **So the handshake is not what stops it.** What stops it was measured in a real browser rather than remembered: on a page that is not cross-origin isolated `SharedArrayBuffer` is **not defined at all**, and with `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` set it exists while `Atomics.wait` still answers `TypeError: Atomics.wait cannot be called in this context` **on the main thread**. A synchronous fork-join therefore has to busy-spin, or the whole fixed-step loop has to move into a worker where blocking is allowed — which is a different architecture rather than a pool behind this seam. And `require-corp` lands on the **consumer's whole site**: every cross-origin resource that does not opt into CORP stops loading, which is fonts, CDN images, embedded video and analytics. The row stays open with its sentinel and those numbers attached. **A row this long is a row that has to be read end to end before it is added to**, which the Animation row above says and which this one had stopped doing: it went on listing joints, ragdolls, raycast, triggers, layers, vehicles and cloth as absent for as long as it took to build every one of them. **The kernel moved to `@driftengine/physics` ** and core re-exports every name, so no import changed; the package imports no other engine package, which makes a simulation with no renderer in its module graph. A shape now carries its **faces** as planes and ordered loops beside the deduped separating directions, and `shapeMassProperties` is exact for a hull by tetrahedral decomposition over them — one build-time addition serving both contact clipping and inertia. `capsuleShape` names what the representation already expressed, two points and a rounding radius. **A cylinder ships, and the measurement that closed it is the one that had kept it open.** This row spent a fortnight calling it a refusal while `README.md`'s gap list called it a gap and a sentinel guarded it — three places, two answers — and what settled the disagreement was a number rather than an argument. The workaround `shape.ts` recommended was an n-gon prism through `hullShape`; `hullShape` refuses more than 64 points, a prism spends two a side, so **thirty-two sides is the wall**, and a thirty-two-sided wheel of radius 1 rolling at 6 m/s **bobs 16 mm** against 49 mm at sixteen sides and 119 mm at eight. No side count can improve that. The refusal's own reversal condition named "a wheel rim, a rolling barrel", and a centimetre and a half of bob on a slow, close, rolling subject is plainly visible — so the workaround did not cover the case the refusal pointed at, and the refusal was withdrawn. The same wheel as a `cylinderShape` bobs **under 2 mm**, inside the solver's own 5 mm slop, and `prismRoll.test.ts` now measures both side by side.

**What it is, structurally, is a second kind of rounding rather than a second shape type.** `ConvexShape.sideRadius` grows a point cloud by a _disc_ perpendicular to the segment through its first two points, where `radius` grows it by a ball — two flat caps, a curved side, a sharp rim. The axis is the shape's own two points rather than a stored vector, so a cylinder baked into world space by a collider carries its orientation the way its position is carried. `mass.ts` gains the two textbook moments in closed form, `shapeBounds` grows by the disc's extent down each axis rather than by the radius on all three, `query.ts` answers a ray with a quadratic and two discs instead of the march a capsule needs, `cloth.ts` pushes a particle out through the same four-region closest point, and `collide/sweep.ts`'s projections carry the disc term. **Contacts are a module of their own**, `cylinderContact.ts`: a curved side enumerates no separating axis, so the axis list is built against the _other_ shape — its faces, its edges crossed with the cylinder's axis, and two directions per vertex — and every one of them is answered exactly by the cylinder's own support. The touching feature is then a cap disc, a side line or a rim point, each clipped differently. It costs **5,492 gzipped bytes, 17.3% of the package**, which is the largest single step this entry point has taken and is what a second representation costs rather than what a constructor costs.

**Building it found a solver bug older than it, and the bug was not about cylinders.** The solver stores each contact anchor in its body's frame and turns it forward through the substeps, which is exact for a face or a corner and wrong for anything round: the point where a rolling ball meets the floor stays at the bottom, and an anchor that turns with the body climbs its side and reports a gap. Measured — **a sphere of radius 1 rolling at 6 rad/s sank 28 mm into the floor and stayed there**, and in the solver baseline scene a sphere rested at 0.3916 where its radius is 0.4. | **Audio** | **The mix is a tree**: `MixConsole` holds buses that nest to any depth, each `input gain → inserts → tap → output gain`, with sends taken from the tap so a fader moves what it sends. Solo silences siblings and leaves ancestors and descendants alone — anything else silences a soloed leaf through its own parent — and a bus born while somebody is soloing arrives already gated, because the gate is a property of the tree rather than an event. The return already carries a convolver built at registration, so `SpatialSource.attachZone` costs one `GainNode` and a per-frame amount. It closes the case the listener model names as the one it cannot serve: a sound inside a cave heard from _outside_ it now carries the cave's tail, because the **source's** position decides its own send. **The budget still binds and it binds per source**: at most two zones sound for one source, because the budget was never about the sends — it is about how many convolvers are audible at once, and a source driving four returns makes four of them audible. **The send is taken before the panner and after the occlusion**: a reverb send comes off the channel on any console and the return is itself a stereo space, so a point-panned tail would arrive from the source's direction rather than from the room, and a sound behind a wall has a muffled tail too. **The trap is that both routings reach one return.** The listener's zones send from a whole bus, so a source on that bus — or on a descendant of it, which is the case a consumer with its own tree actually builds — is already reaching the return whenever the listener is in the same space, and its own send is then a second copy that is inaudible as a fault and merely wrong. `attachZone` walks the parent chain and says so, once per misconfigured bus rather than once per source. **Ambisonics ships**: `createAmbisonicSoundfield` takes a four-channel first-order field in **ACN order with SN3D normalisation**, which is what a B-format recording carries and what every capture tool emits — a private ordering would be one shuffle nobody could see, in a file this engine did not make. ## 3. Two limits that are measured rather than assumed

**The lit pass uses ten of WebGL2's guaranteed sixteen texture units.** Three
directional cascades at 0–2, the point-shadow array at 3, then the four material maps together —
surface at 4, normal at 5, ORM at 6, emissive at 7 — the environment probe at 8, the froxel table
at 9, and **six free**. The probe was always there and this paragraph did not count it, which is
corrected rather than quietly restated; `textureUnitBudget.test.ts` derives the total from the
highest unit now rather than counting it, because counting it is what got it wrong. It once fill all sixteen exactly — the twelve point-shadow cubemaps were twelve separate
`samplerCube` declarations, because GLSL ES cannot index a sampler array — and that was found from
a phone, on a scene lit almost entirely by point lights, rendering 0.7% of the frame above black.
`textureUnitBudget.test.ts` holds the arithmetic, including that a light now costs a _layer_ rather
than a unit, which is the property most easily undone by accident.

**They are what the material maps come out of, and all three have now been spent.** The normal map
took the first, the ORM map the second and the emissive map the third, each named in
`textureUnitBudget.test.ts` before it was taken so that the change spending one had to read what it
was spending. **Phase 1.3 is complete**: the material core is tangents, `ATTR_TANGENT`, and normal,
ORM and emissive maps, end to end from glTF through the container to both backends.

**The froxel table spends one unconditionally, and that is what a runtime branch costs.** Clustered
lighting is a branch on a uniform rather than a permutation — see the Lights row — so its sampler is
declared in every profile, and a declared sampler needs a complete texture bound whether or not the
branch reads it. With clustering off the binding is a single texel rather than 292 KB.

**`MAX_POINT_LIGHTS` is 16, and it was 10 because ten was where the units ran out.** Sixteen lights
is twenty pool layers plus two live ones at 1024², 92.3 MB, against the 100.7 MB the sixteen cubes
it replaces cost — fewer bytes and six more shadowed lights. Eighteen is where the memory exactly
equals the old cost.

**Sixteen is what the engine declares and not always what a part will link.** Twenty of the lit
shader's uniform arrays are sized by that budget and fourteen by the four area lights, and GLSL ES
spends a whole row of the fragment uniform grid per array _element_ whatever its base type: the full
budget is **440 rows**, an Adreno 740 offers **256**, and WebGL2 guarantees only **224**. So the
WebGL2 renderer counts the shader it is about to compile and builds at the largest budget that fits
— 8 lights and 2 rectangles is 252 rows with point shadows still compiled in, and 4 and 1 is 158.
`renderer.shadedLights` reports what was resolved; `maxLights` and `maxAreaLights` are the ceiling
for a consumer who wants to choose one. WebGPU has no such ceiling and reports all sixteen.

**On WebGPU the widest permutation asks for seven sampled textures and four samplers**, against an
adapter offering forty-eight and sixteen. It asked for seventeen and three before, and the
seventeen was why `select.ts` has to request a raised limit at all.

**The point-shadow filter cap is `MAX_FILTER_RADIUS = 0.25`, up from 0.07.** Four attempts went
into widening it and none worked, for one reason: a wide angular filter on a cube map crosses face
seams, which draws as straight lines radiating from beneath the light. Seven separate reports
pointed at those lines. An octahedral map is one projection over the whole sphere and has no faces
to cross, so the cap came off the floor the seams had pinned it to.

**0.25 rather than further, and the ceiling is arithmetic.** The filter width and the strength fade
are driven by the same quantity, so a shadow at `sourceRadius * spread` of 0.625 has faded to
nothing and there is no blur left to apply; at 0.25 it is still at 84% strength and plainly a
shadow. A sweep at 0.07, 0.15, 0.25, 0.40 and 0.625 was captured on both point-lit scenes and none
of them drew a line, a band or a speckle — **and the GPU timings were too noisy to choose on**, two
runs of one build differing by more than two runs of two builds. `scripts/docs.test.mjs` asserts
the number above is the number in `lobes.ts`, because this was prose and prose is what drifted.

## 4. What the record got wrong

The document this file replaces was written eight days and one major version earlier, and three of
its claims are worth stating as corrections rather than quietly dropping.

**The sampler gate is not absolute, and it was named as the reason several features were
impossible in their obvious form.** §2.1 of that document counted sixteen units of sixteen with
nine wanted and none available. On WebGPU that stopped being true when the shadow bindings were
collapsed into one sampler declaration, and nobody reconciled the document with it. See §3 above
for the arithmetic on both backends. The gate is a WebGL2 debt.

**The frame-graph deferral has come due.** §2.5 quoted `renderer.ts` at 3,574 lines and deferred
the decision about a pass graph to whatever the WebGPU work concluded about that file. What it
concluded was a second hand-ordered renderer. `renderer.ts` is now **7484 lines** and
`webgpu/renderer.ts` is **13,004**, for 20,488 lines of pass order held by hand across two files.
The WebGPU figure is rising rather than falling because every verb now carries both paths: the
recording the graph replays and the direct calls `?graph=0` still uses. Both exist until the
switch stops being reversible, which is an open decision in the design rather than an oversight.
Those two numbers are asserted by `scripts/docs.test.mjs` rather than typed, because the first one
was 556 lines wrong within a week and nothing noticed.

**Gaussian splats left `README.md`'s gap list without it being edited, which is the failure the sentinels exist to catch and the reason this section is kept.** `@driftengine/splats` shipped the readers, the off-frame sort and the pass, and the guard stayed green throughout because it named `evaluateSh` — a symbol for the one part that genuinely did not land. A sentinel that is narrower than the row it stands behind reports the row as absent long after most of it arrived, so the sentinel now names view-dependent colour, which is what is left of it, and the row says the same. Recorded here rather than in `README.md`: that document lists gaps, and how a gap list went wrong is this one's business.

**`drift/physics` said it bound joints and never has, found 2026-08-27.** Its own header in
`packages/script/src/bindings/core.ts` read "Track B, complete: bodies, joints, queries, sensors, a
controller and ragdolls", and the capabilities under it are bodies, contacts, queries and
forces — no joint verb, no controller, no ragdoll, and no way for a script to make one. The
sentence was written from the _track's_ deliverables rather than from the list beneath it, which is
the same failure as a binding written from memory of what a camera ought to have: the first version
of `drift/camera` described `lookAt` and `setPosition`, which `CinematicCamera` does not have.

The header is corrected and **the gap is left open on purpose**, with the reason recorded there:
`JointDesc` carries twenty optional fields, so a script-side constructor is either an enormous
signature or a builder this language has no shape for. That is a decision somebody has to take
deliberately, and taking it badly would put a wrong-by-construction surface in front of every script
author. **§1's "Scripting reach" row counts thirteen modules and is still right** — the module is
reachable; what it reaches is narrower than its own comment claimed.

**`drift/audio` said it bound the mix and the rhythm and binds neither, found 2026-08-27.** Its
header called itself "the richest surface available, because Track G is complete: playback,
placement, the mix, and the rhythm the music is doing", over five capabilities: a slot, two ways to
play it, and `distanceGain` and `stereoPan`. No mix verb, no rhythm verb, no HRTF-panned source, no
listener, no reverb zone. **That is the same failure as `drift/physics` above and the same failure
as the first `drift/camera` binding**, three times in three files, and the shape is identical every
time: a header written from what a _track_ delivered rather than from the array beneath it.

Corrected, and **left open on purpose** for the same reason as joints: `MixConsole`,
`AudioListenerGraph`, `SpatialSource` and `ReverbZone` are stateful objects with lifetimes, and a
script surface for them is a design about handles and ownership — who disposes a source, what
happens to its probe slot, whether a zone outlives the script that made it — rather than a table
entry.

**The pattern is worth naming, because a fourth is likely.** Every binding file's header is prose
about a subsystem, and nothing asserts that it describes the capabilities in its own file. A guard
that read the `define` calls and checked the header mentioned no verb the array lacks would have
caught all three; that is a test somebody should write, and it is not written.

**None of its running order was built.** Not splats, rigid node animation, spot lights, general
per-instance transforms, the sampler filter mode, octahedral shadows, PBR inputs, image
environments, clustered lights, depth of field or area lights. The time went to the WebGPU port,
which was the right call and was never reconciled with the plan it displaced. That is the failure
this document's sentinels exist to prevent repeating.

## 5. The sentinels

Each row names a symbol that would exist if the capability did. `scripts/docs.test.mjs` asserts
every one is still absent from `src/`, so the commit that builds spot lights is the commit that has
to correct this document. Patterns are matched against source with comments stripped, because prose
in a comment mentioning a spotlight is not a spot light.

**A second sentinel retired the same day, and it would not have fired.** `clustered-lights` named
`uClusterGrid`, and the uniforms that actually landed are `uClusterTable`, `uClusterFrustum` and
`uClustered` — so clustered lighting arrived with the guard green, exactly as frustum culling and
LOD did under names the rows had guessed wrong. **That is the third time**, which is
enough to stop calling it a near miss: a sentinel is a reminder to correct this document, not a
detector, and the habit that keeps it honest is correcting the row in the commit that lands the
capability rather than waiting for a red suite to ask.

**A fourth miss, and this one is recorded before it could be discovered.**
`image-based-lighting` named `irradianceSh`, and what landed is a _file_ called `irradianceSh.ts`
whose exported symbols are `projectIrradiance` and `evaluateIrradiance`. Patterns are matched
against source with comments stripped, and a filename is neither — so the guard stayed green
through the commit that built half the capability. It was corrected because the plan said to,
which is the only reason it was corrected at all.

**That is the fourth, and the row above is narrowed rather than deleted for that reason.** What was
left of it, `prefilterEnvMap`, was a name for a thing that did not exist yet and would be written by
somebody who had not read this document — so it was as likely to miss as the other four.

**It did not miss, 2026-08-25.** The guard fired on the commit that built the prefilter, naming
`packages/core/src/render/backend/webgpu/renderer.ts`, and it fired on an _import statement_ rather
than on a definition — which is the first time one of these has been caught by the mechanism rather
than by somebody remembering. A file name is not source; a path in an `import` is. The sentinel is
replaced with `environment-loader`, which names the piece still absent, and the habit is unchanged:
correct the row in the commit that lands the capability, because a green suite is not evidence that
nothing landed.

**A sentinel retired on purpose, 2026-08-24.** `compute-pipelines` named `createComputePipeline`
and is gone from the block below, because the engine now builds one: the froxel binner in
`webgpu/clusterBinner.ts`. The row it guarded is corrected above rather than deleted, since what a
reader wants to know is not that a symbol appeared but which backend can do what.

**A sentinel narrowed on purpose, 2026-08-24.** `clustered-lights` named
`buildLightClusters|uClusterGrid` and the first of those now exists, in a file nothing draws with.
The row was narrowed to `uClusterGrid` rather than corrected away, because that uniform is the
moment the _lit pass_ reads a froxel table — which is when a consumer's scene is lit differently
and when the capability becomes real. A sentinel that fires on groundwork reports a capability
that does not exist, and the failure that costs is a green row nobody trusts. **Narrowing is only
honest when the remaining symbol is strictly later than the one dropped**; here it is, and the
Lights row above says exactly what was built in the meantime.

**Two sentinels added as Track A closed, 2026-08-25.** Four were dropped as the row landed —
`skeletal-animation`, `animation-clips`, `inverse-kinematics` and `morph-targets` — which left
`README.md` naming an animation gap no sentinel backed, and `docs.test.mjs` said so. The two that
replace them name what the row genuinely leaves: **root motion**, which is a decomposition of the
root track and belongs beside `sampleClip`, and **skinned shadow casting**, where the depth pass
has its own vertex shader and its own permutation question. Both are strictly later than anything
Track A built, which is what makes them honest rather than a guard being kept alive for its own
sake.

**And one of those two closed without a word, which is the splats failure in its
second and worse form.** `ce91c4c` built skinned shadow casting end to end: `DEPTH_SKINNED_VERT`
and its WGSL twin, `depthSkinnedProgram` and `shadowSkinnedLayout` on the two backends, and
`ShadowCasterSink.skinnedMesh` carrying the palette so a running figure stops throwing the shadow
of a statue. The sentinel stayed green throughout, because it named `uSkinnedDepth` and
`skinnedDepthVariant` — two symbols nobody wrote and nobody was ever going to. Both documents went
on calling the capability absent for a fortnight of releases, and it was found by reading the
renderer rather than by anything failing.

The rule this leaves, alongside the widening rule two paragraphs below: **a sentinel invented for a
capability nobody has begun is a guess at somebody's future naming, and a guess is what it will be
wrong about.** The two that read as real symbols here — `class MeshShape`, `cylinderShape` — are the
ones taken from the vocabulary the package already uses. A sentinel with a `u` prefix for a uniform
this codebase would name from its shader source is the shape to distrust, and the way to check one
is to ask which file would have to declare it.

**`cylinderShape` fired, and it is the second one caught by the mechanism rather than
by somebody remembering.** The commit that built the cylinder named the function exactly that,
because the paragraph above had already said why: a sentinel drawn from a package's own vocabulary
is a sentinel somebody will write without having read this file. It named
`packages/core/src/index.ts` — the barrel's re-export rather than the definition — which is the
same thing the prefilter's did, and is fine: the guard's job is to make the commit correct this
document, not to point at the right line.

**A sentinel that fired despite a plan saying it would not, 2026-08-25.** `morph-targets` named
`morphTarget|blendShape`, and the plan that landed the feature predicted neither would match its
chosen names — `morphTargets`, `morphTexelIndex`, `setMorphWeights` — so it scheduled a widening
before the work. The widening was never needed: `morphTargets` contains `morphTarget`, and the
guard fired on its own. Recorded because the mechanism's stated limit is that it only fires on a
name somebody guessed, and here the guess was close enough by accident rather than by design. A
prediction that a guard will not fire is worth checking against the guard rather than trusted.

**A narrowing that was one step early, and the correction is the point.**
`skeletal-animation` was narrowed to `skinMatrix` on the argument that it names "the moment the lit
pass actually skins". It does not: it names the moment a _shader source_ defines the function, and
that arrived a commit before any draw selected the variant that uses it. So the guard fired a
second time on groundwork, having been narrowed once already.

The sentinel is **dropped rather than narrowed again**, because narrowing twice is the guard being
talked out of firing, and the Animation row now states in words exactly what works and what does
not — which is what a reader needs and what no single symbol was ever going to carry. The lesson is
the one below in a sharper form: a sentinel is a guess about a _name_, and a name in source is not
evidence about behaviour. Where the two come apart, the row does the work.

**A sentinel narrowed on purpose, 2026-08-25.** `skeletal-animation` named
`skinMatrix|jointMatrix|inverseBind`, and the last of those now exists — in `Skeleton`'s
constructor, which resolves a pose into a palette and which no shader reads. **That is groundwork,
not a capability**: a row corrected there would claim the engine skins when nothing on screen
moves. Narrowed to `skinMatrix`, which is the moment the _vertex stage_ multiplies a position by a
joint, and which is strictly later than the two names dropped — the condition that makes narrowing
honest rather than a guard being talked out of firing. The Animation row below says what arrived in
the meantime.

**A sentinel only fires if the implementer picks the name it guessed, and that is a real limit
rather than a quibble.** Frustum culling and LOD landed as `sphereInFrustum` and
`lodForBounds`, while the rows guarding them named `cullAgainstFrustum|isSphereVisible` and
`selectLod|lodForDistance` — so both capabilities arrived with the suite green. One of the guessed
names was worse than the real one on purpose: `lodForDistance` is exactly the design this engine
rejected, and matching it to satisfy a guard would have been the guard choosing the API. Widen a
pattern when a near miss is found, and read a green suite as "no symbol I thought of" rather than
as "nothing was built".

**A sentinel that survived the capability it guarded, found 2026-08-26.** `gaussian-splats` named
`evaluateSh|shDegree`, and `@driftengine/splats` shipped the readers, the sort and the pass without
either appearing — because those two name **view-dependent colour**, which is the one part of a
splat capture that did not land. So the guard was correct about its symbols and wrong about its
subject for as long as the package existed, §2 lost its splats row without §1 gaining one, and
`README.md` went on telling a reader that Gaussian splats were absent while the package table three
screens above listed them with a measured size.

Renamed to `splat-view-colour`, which is what the pattern actually watches. **This is not the fifth
near miss but a different failure**: the earlier four were names nobody guessed right, and here the
name was fine and the _row_ it belonged to was never written. A sentinel guards a symbol; only a
row says what the symbol is for, and a sentinel with no row is a guess with nothing to correct.

**And it fired, on the commit that built the capability** — naming
`packages/splats/src/splatCapture.ts`, where `shDegree` first appears. That is the third of these
caught by the mechanism rather than by somebody remembering, and it is the first where the _rename_
is what made it possible: the guard had been watching the right symbols under the wrong row for as
long as the package existed.

**One sentinel guarding two capabilities, split 2026-08-27.** `ambisonics` named
`ambisonic|foaDecode|sourceZone`, and the third of those is a different capability from the
other two: a source-attached reverb zone is a second _routing_ into a convolver that already
exists, where ambisonics is a decoder and a soundfield format. Building either would have
fired the guard for the one that had not been built, and the row would then have been
corrected for both — which is the splats failure in a third form: **a sentinel is honest only
while every symbol it names belongs to one row.** Split into `ambisonics` and
`source-reverb-zone`, with a row each, before either was begun.

**A sentinel that would not have fired, and the row was corrected anyway, 2026-08-27.**
`elliptical-friction-cone` named `ellipticalFriction|frictionEllipse`, and what landed is
`solveFrictionCone` beside `solveTangent`, `solveDistance` and `solveRevolute`, with the
choice carried by a `FrictionModel` of `'box'` or `'elliptical'`. Neither guessed symbol
occurs. **The names were not bent to match**, for the reason §5 already records about
`lodForDistance`: a sentinel that chooses an API is a guard doing the design's job, and
`solveFrictionCone` is what this file's own vocabulary calls that function. So this is the
sixth miss, it was known in advance, and the row was corrected in the commit that landed the
capability — which is the habit the paragraphs above say is the only thing that works.

**A sentinel that fired, which is the first one in this file's history to.**
`area-light-shadows` named `areaShadow|uAreaShadowMap`. One of those two guesses was right and
one was wrong — the function is `areaShadow` and the uniform is `uAreaShadowLayer`, because an
area shadow is a _layer_ of the point-shadow array and never a map of its own — and a guard
joined by `|` needs one hit, which is what the `elliptical-friction-cone` miss above is the
argument for. So the row was corrected in the commit that landed the capability, prompted by a
red suite rather than by somebody remembering: `every absent capability is still absent` failed
with "area-light-shadows now exists (packages/core/src/index.ts) — correct CAPABILITIES.md".
That is the whole mechanism working, once, after six misses.
